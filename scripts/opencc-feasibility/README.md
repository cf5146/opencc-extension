# Official OpenCC source feasibility probe

This is phase 1 of the approved conversion rewrite evaluation. It changes no production engine, popup, settings, DOM traversal, or release pipeline. The existing application still runs its original converter.

## Fixed inputs

- BYVoid/OpenCC `ver.1.4.2`, commit `025f371dc76b598d77384fbdab90c937471844d8`; official working tree must be clean.
- Emscripten 4.0.22 / emsdk commit `15915cad554b707837024dc2758b6a1c5b94b036`; Python 3.13.9, CMake 3.31.10, Ninja 1.13.0.
- Tested host: Debian 13.6 x86_64 WSL, GCC 14, Windows Node 26.12.1, Edge 155.0.4283.62. This is a verified environment, not a promise of identical binaries on arbitrary hosts.
- Five official configurations (`s2t`, `s2tw`, `s2twp`, `s2hk`, `tw2sp`), each with mmseg and Jieba. Library default `includeTofuRiskDictionaries=true`.
- Fixtures are snapshots of `test/testcases/testcases.json` and `plugins/jieba/tests/data/jieba_comparison_testcases.json` at the fixed commit. Their original JSON/JSONC bytes and hashes are retained. `fixtures/LICENSE.opencc` applies to the snapshots.

## Build on WSL

Host GCC/G++, curl, git, tar, and standard Linux utilities are prerequisites. Use a dedicated ext4 cache, not the Windows mount, for tools and build directories. Neither script changes shell profiles or installs system packages. Initial source/tool downloads need network; conversion after packaging does not.

```bash
BASE="$HOME/.cache/opencc-feasibility-01a166ee"
# Run from this directory as mounted in WSL.
bash bootstrap.sh "$BASE"
bash reproduce.sh "$BASE"
```

`reproduce.sh` produces `dist/manifest.json` and the WASM/resources. `prepare.mjs` reads configuration bytes from Git objects, so autocrlf does not change them. Native dictionaries and merged Jieba data are generated by official tools from the same source. `artifact-lock.json` is the reviewed output identity; rebuilds do not overwrite it. Updates are human initiated: change pins, rebuild, rerun verification, review the manifest diff, and only then replace the lock. Normal application builds never run these downloads.

For a genuinely fresh compilation with the existing toolchain:

```bash
OPENCC_BUILD_DIR="$BASE/check-wasm" OPENCC_NATIVE_BUILD_DIR="$BASE/check-native" bash reproduce.sh "$BASE"
```

Compare all resource/artifact hashes against `artifact-lock.json`. The recorded local fresh rebuild matched all 32 files byte for byte. This does not establish cross-platform reproducibility.

## Verify on Windows

From this directory, install the private validation dependencies (separate from the application lockfile):

```powershell
npm ci --ignore-scripts
node --test acceptance.test.mjs
node --test verification.test.mjs
node evaluate.mjs
# Set this to the installed @playwright/cli 0.1.22 JavaScript entrypoint.
$env:PLAYWRIGHT_CLI = 'C:/path/to/node_modules/@playwright/cli/playwright-cli.js'
node edge-test.mjs
node verify.mjs
```

Native npm packages `opencc@1.4.2` and `opencc-jieba@1.4.2` supply the independent Windows native oracle. The optional Windows binary packages must be available. Browser automation uses a dedicated headless Edge profile and an unpacked probe extension, closes it after testing, and leaves normal browser profiles alone. `verify.mjs` checks current artifact hashes, the reviewed lock, tested manifest identity, all native/Edge corpus comparisons and complete long-output hashes. Run fresh evaluation before trusting results after any change.

## Boundary and limits

- Official core and `JiebaSegmentation.cpp` are unchanged. A small static factory replaces native `dlopen` discovery; only five named configurations are exposed.
- Complete UTF-8 inputs use heap allocation and explicit byte lengths. No truncation, chunking, mode fallback, CDN, or external model fetching occurs.
- Official `Segments` still uses NUL-terminated strings internally. Embedded NUL and malformed UTF-16 are rejected before conversion rather than silently losing text. Preserve the original text when integrating errors into the product.
- WASM output is borrowed from a converter; JavaScript copies it before the next call. Input allocations are freed in `finally`, handles in `close()`.
- This minimal session caches all requested configurations. It is an evaluation boundary, not the final product cache policy. Ten cached converters reach roughly 571 MiB linear memory; one default Jieba converter starts around 111 MiB. `close()` frees handles but WASM linear memory cannot shrink; reclaim it by terminating the Worker.
- Timing is local observational evidence, from fresh Workers within a running browser. It is not a cold machine benchmark or a quality/speed ranking. Linear memory excludes JS heap, filesystem storage, browser/process overhead and transient copies.
- Finite native parity is not a universal guarantee. Per-text-node conversion still loses context across DOM boundaries. Production dynamic-page/selection/settings behavior remains for the next phase.
- Reported package size covers three runtime artifacts plus 29 selected resources. It excludes the manifest, harness, tests, license packaging, full extension and ZIP overhead. A release needs a complete third-party notice bundle from the pinned source dependencies.

See `RESULTS.md` and `output/*.json` for measured evidence and the next-phase recommendation.
